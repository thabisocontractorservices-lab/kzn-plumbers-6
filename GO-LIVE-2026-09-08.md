# KZN Plumbers — direct code-first release

This release uses the existing GitHub repository, Vercel project and Supabase database. It requires no new hosted project, Docker installation, local test run, review cleanup or SQL migration.

## Deploying the update

1. Use the reviewed code on release/kzn-growth-rebuild in thabisocontractorservices-lab/kzn-plumbers-6.
2. Merge that release into the production branch (main). A new Vercel build must use the Production-scoped environment variables already connected to the live database. Do not promote a build that was compiled with staging variables.
3. Vercel builds the code in the cloud. Node 24.x is pinned in package.json; this is Vercel's runtime, not a requirement to upgrade your Mac.
4. When Vercel shows Ready for that commit, open the site and sign in to /admin using an existing confirmed administrator account.
5. Do not run migration 007, its rollback, the review-archive transaction, or a database reset as part of this code-only release.

The GitHub merge and Vercel Ready state are separate milestones. A successful local build does not prove that your protected Vercel environment variables and database configuration are correct.

## Included admin functionality

- Overview: actual published/unpublished listing, account, pending-claim, booking and stored-review counts. Missing lead tracking says Not tracked rather than inventing zero leads.
- Listings: search and pagination, inspect evidence, publish/unpublish without deleting the business, and separate credential-check controls only when the required evidence fields exist.
- Claims: confirmed-account ownership review, mandatory evidence/rejection notes, conditional profile linking and explicit partial-failure messages. No automatic phone-match claims.
- Reviews and history: latest review per signed-in account/business shown as current, older entries retained in the original database, and private downloadable history exports.
- Bookings: administrator confirmation/cancellation; plumber dashboard outcome buttons only when their fields exist.
- Accounts: bounded, server-authorised account listing.
- Policies and reporting: read-only anonymous-row visibility checks, certificate-bucket status, schema capability report and optional policy-definition export SQL. No arbitrary SQL endpoint and no automatic policy edits.
- Public review concern links prefill the contact flow. Reports go to the configured admin email; no database ticket inbox is claimed where no ticket table exists.

## Public and account improvements

The KZN homepage, regional/service collections, genuine profile content, contact links, policy/help pages and sourced resources remain. Search and Back/Forward now preserve filters without duplicate requests. Ranking by Google rating is distinct from neutral name ordering. Service geography is narrowed to real stored areas, not invented suburb coverage. Historical profile URLs are not automatically deindexed just for having sparse data. Sitemaps paginate the full inventory and use real dates.

Registration and claims use confirmed sessions. Private certificate downloads use freshly generated, access-checked temporary URLs. Bookings use existing tables with validated server-side writes and preserve contextual details in legacy notes. Reviews are not silently rewritten, merged or erased.

## Existing Vercel configuration

Keep these values in Vercel, not GitHub:

- NEXT_PUBLIC_SUPABASE_URL
- NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY (or the supported legacy anonymous-key variable)
- SUPABASE_SERVICE_ROLE_KEY — server only
- NEXT_PUBLIC_SITE_URL=https://www.kznplumbers.co.za
- RESEND_API_KEY, ADMIN_EMAIL, FROM_EMAIL for transactional mail
- CRON_SECRET and GOOGLE_API_KEY for the existing Google-review refresh

Admin access requires a confirmed session, profiles.role=admin, and an allowed email. By default the existing administrator identities from the handoff are allowed; ADMIN_ALLOWED_EMAILS can explicitly override the list. It does not grant admin status to an account by itself.

## Optional analytics

GA remains off until GA_AUTOMATIC_MEASUREMENT_DISABLED=true confirms automatic Enhanced Measurement/search/form/outbound-link collection has been disabled in the existing stream. This avoids collecting message URLs or query/contact data. Visitors still choose whether to allow optional analytics. Missing first-party lead-event storage does not block booking or contact actions and is reported honestly in admin.

## What this code does not change

- No Supabase tables, indexes, RLS policies, Storage bucket settings, review records or live credentials are changed automatically.
- The five older reviews discussed earlier are still stored. They appear as earlier history; they have not been physically moved into the prepared private SQL archive.
- Existing publicly readable certificate/account policies remain a database-level risk. First-party API checks do not repair direct Supabase access, writable legacy roles, security-definer views/functions, or previously issued signed URLs. The admin report surfaces observations, not a blanket security approval.
- Review/claim prechecks are not cross-request database constraints. Multi-step ownership and upload actions are not a database transaction; uncertainty is surfaced instead of reported as success.
- There are no invented lead counts, verification dates, availability confirmations, ratings or guaranteed ranking promises.

For a code regression, retain the previous GitHub/Vercel deployment reference. Because this release does not migrate the database, code rollback does not also require a database rollback. Previously reported credential exposure still needs proper credential rotation in the service dashboards if it has not already been addressed; never paste secrets into chat.
